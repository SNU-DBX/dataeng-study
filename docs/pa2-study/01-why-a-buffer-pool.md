# 01 · 버퍼 풀은 왜 존재하는가

!!! abstract 목표
    버퍼 매니저가 DB 엔진에서 어떤 자리를 차지하는 레이어인지, 그 위와 아래에는 무엇이 있는지 파악한다.

관계형 테이블은 디스크 위에서 고정 크기 **페이지**(PostgreSQL은 8 KB, `BLCKSZ`)의 나열로 존재한다.
튜플 하나를 읽고 쓰는 일은 물리적으로는 그 튜플이 들어 있는 페이지를 읽고 쓰는 일이다. 이 접근이
매번 디스크까지 내려간다면 데이터베이스의 속도는 곧 디스크의 속도가 된다. 그래서 DBMS는 페이지
크기의 **프레임** 배열을 메모리에 고정 크기로 잡아 두고, *페이지 식별자 → 프레임* 매핑을 함께
관리한다. 이 배열이 **버퍼 풀**, 매핑이 **버퍼 테이블**이고, 여기에 무엇을 언제 쫓아내고 언제
디스크로 되돌릴지 결정하는 정책까지 묶은 것이 **버퍼 매니저**다.

```text
      SQL executor                          "give me block 42 of table foo"
            │
            ▼
   ┌───────────────────────────────────────────────────────────────┐
   │  BUFFER MANAGER                                               │
   │                                                               │
   │   buffer table          buffer pool (NBuffers × 8 KB frames)  │
   │   (hash: tag → id)      ┌──────┬──────┬──────┬──────┬──────┐  │
   │   ┌────────────────┐    │ blk  │ blk  │ free │ blk  │ blk  │  │
   │   │ (foo,0,42) → 3 ├───▶│  17  │  99  │      │  42  │   8  │  │
   │   │ (foo,0,17) → 0 │    └──────┴──────┴──────┴──────┴──────┘  │
   │   │      …         │       0      1      2    ▲ 3      4      │
   │   └────────────────┘                          └── buf_id      │
   │                                                               │
   │   descriptors: per frame — tag, refcount, usagecount, flags   │
   └───────────────────────────────────────────────────────────────┘
            │  miss ⇒ read()                    │  dirty ⇒ write()
            ▼                                   ▼
      ┌─────────────────────────────────────────────────┐
      │  base/<dboid>/<relfilenode>   (1 GB segments)   │
      └─────────────────────────────────────────────────┘
```

## 1 · 엔진 안에서의 위치

버퍼 매니저는 **"메모리 위의 페이지"라는 추상을 제공하는 계층**이다. 위쪽에는 튜플과 인덱스 엔트리를
다루는 코드가, 아래쪽에는 파일과 블록을 다루는 코드가 있고, 그 사이의 캐싱을 전담한다.

| 계층 | 다루는 단위 | 대표 코드 |
|---|---|---|
| 파서 · 플래너 · 실행기 | 튜플, 행 | `executor/` |
| 접근 메서드 (heap, btree) | 튜플 ↔ 페이지 | `access/heap`, `access/nbtree` |
| **버퍼 매니저** | **페이지 ↔ 프레임** | **`storage/buffer/`** |
| 저장 매니저 (smgr / md) | 블록 ↔ 파일 오프셋 | `storage/smgr/` |
| OS 페이지 캐시 · 디스크 | 파일, 섹터 | OS 커널 |

위 레이어가 버퍼 매니저에게 요구하는 것은 두 가지뿐이다. "이 페이지를 메모리에 올려 주소를
달라"(`ReadBuffer`), 그리고 "다 썼으니 놓아 준다"(`ReleaseBuffer`).아래 레이어에는 반대로 `smgrread` / `smgrwrite` 과 같은 읽기/쓰기 호출만 내려가는 것이 원칙이다.
